# CLAUDE.md — Платформа анализа госзакупок

## Обзор проекта

Веб-платформа для автоматизированного сбора и анализа данных реестра договоров с сайта [goszakup.gov.kz](https://goszakup.gov.kz/). Пользователь вводит БИН компаний, система автоматически собирает данные по договорам, вычисляет разницу сумм и формирует Excel-отчёт.

**Стек:** Python + Streamlit + Playwright (или Selenium) + openpyxl
**Язык интерфейса:** Русский
**Авторизация на сайте:** не требуется

---

## Технический стек

| Компонент | Библиотека / Инструмент                                                                            |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| UI                 | `streamlit`                                                                                                          |
| Парсинг     | `requests` + GraphQL API goszakup.gov.kz (Bearer-токен)                                                         |
| Excel              | `openpyxl`                                                                                                           |
| Прогресс   | `st.progress` + `st.status`                                                                                        |

> **Примечание:** Используется официальный GraphQL API сайта госзакупок — никакого headless-браузера не требуется.

## Функциональность

### 1. Форма ввода БИН

- Одно поле ввода БИН по умолчанию при старте
- Кнопка **"+"** для добавления дополнительных полей (динамически)
- Кнопка **"−"** для удаления поля
- Валидация: БИН должен состоять из 12 цифр
- Кнопка **"Запустить анализ"** — запускает весь пайплайн

```
[ БИН: ________________ ] [−]
[ + Добавить БИН ]
[ Запустить анализ ]
```

---

### 2. Алгоритм парсинга (scraper.py)

Для **каждого** введённого БИН выполняется следующая последовательность:

#### Шаг 1 — Навигация

1. Открыть `https://goszakup.gov.kz/`
2. Перейти: **Реестры → Договоры → Реестр договоров**

#### Шаг 2 — Фильтрация

3. В поле **"Поставщик"** ввести БИН компании
4. В поле **"Статус договора"** выбрать следующие статусы (мультивыбор):
   - `Действует`
   - `Передан. Действует`
   - `Создано доп.соглашение`
5. Нажать кнопку **"Найти"**

#### Шаг 3 — Сбор ссылок

6. Дождаться загрузки таблицы результатов
7. Собрать все гиперссылки на договоры из таблицы
8. Обработать пагинацию (если результатов несколько страниц — пройти все страницы)

#### Шаг 4 — Парсинг каждого договора

Для каждой ссылки:
9. Открыть страницу договора
10. В разделе **"Общее"** найти и извлечь:
    - `Номер основного договора в реестре договоров` → **текстовое поле**
    - `Краткое содержание договора на русском языке` → **текстовое поле**
    - `Срок действия договора` → **текстовое поле**
    - `Общая итоговая сумма договора` → **числовое поле**
    - `Общая фактическая сумма договора` → **числовое поле**
11. Вычислить разницу:
    `` Разница = Общая итоговая сумма договора − Общая фактическая сумма договора ``
12. Сохранить: БИН, номер договора, краткое содержание, срок действия, итоговая сумма, фактическая сумма, разница, URL договора

---

### 3. Прогресс-бар

Отображать пользователю:

- Текущий обрабатываемый БИН (например: `Обработка БИН 123456789012... (1/3)`)
- Текущий договор (например: `Договор 45 из 120`)
- Общий прогресс-бар `st.progress()`
- Статусные сообщения через `st.status()` или `st.empty()`

### 4. Excel-отчёт (excel_export.py)

#### Структура файла

- **Один лист "Договоры"** — единая сводная таблица по всем БИН сразу
- Лист **"Сводка"** — агрегированные итоги по каждому БИН и общий итог

#### Столбцы листа "Договоры"

| № | Столбец                                                                       | Описание                                                                                               |
| -- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| A  | **БИН компании**                                                    | БИН из поля ввода                                                                                |
| B  | **Номер договора**                                                | Номер основного договора в реестре договоров                            |
| C  | **Краткое содержание**                                        | Текст из поля "Краткое содержание договора на русском языке" |
| D  | **Срок действия договора**                                 | Дата начала — дата окончания                                                           |
| E  | **Общая итоговая сумма договора (тенге)**       | Числовое поле                                                                                      |
| F  | **Общая фактическая сумма договора (тенге)** | Числовое поле                                                                                      |
| G  | **Разница (тенге)**                                                | Итоговая сумма − Фактическая сумма                                               |
| H  | **Ссылка на договор**                                           | Кликабельная гиперссылка на страницу договора                         |

#### Форматирование

- Заголовки: жирный шрифт, серая заливка
- Числа в столбцах E, F, G: числовой формат с разделителем тысяч (`#,##0`)
- Столбец G: отрицательные значения подсвечиваются красным
- Столбец H: активные гиперссылки через `openpyxl` (синий цвет, подчёркивание)
- Ширина столбцов подстраивается под содержимое
- Шрифт: Arial 10

#### Лист "Сводка"

- Суммарная итоговая и фактическая суммы по каждому БИН, разница
- Общий итог по всем БИН

- Файл именуется: `goszakup_report_YYYYMMDD_HHMMSS.xlsx`

## Режимы парсинга

Платформа поддерживает два режима анализа:

1. **Анализ реестра договоров** — парсинг договоров по введённым БИН (описан выше в разделе "Функциональность")
2. **Анализ объявлений** — парсинг закупочных объявлений с выделением информации о победителях

### Режим 2: Анализ объявлений (scraper_announcements.py)

Пользователь выбирает режим "Анализ объявлений" и указывает дату из календаря.

#### Алгоритм парсинга объявлений

1. Открыть `https://goszakup.gov.kz/`
2. Перейти: **Закупки → Поиск объявлений**
3. Установить фильтры поиска:
   - **Статус:** выбрать `Завершено` и `Формирование протокола итогов` (мультивыбор)
   - **Предмет закупки:** выбрать `Работа`
   - **Сумма закупки с:** ввести `1 500 000 000`
   - **Протокол итогов с:** ввести дату, выбранную пользователем
   - **Протокол итогов по:** ввести дату, выбранную пользователем
4. Нажать кнопку **"Найти"**
5. Дождаться загрузки таблицы результатов с объявлениями
6. Обработать пагинацию (если объявлений больше на одной странице)

#### Для каждого объявления:

7. Открыть страницу объявления
8. Проверить вкладку **"Договоры"**:
   - **ЕСЛИ есть данные в "Договоры":** перейти во вкладку "Информация о победителях" (шаг 9б), затем к следующему объявлению
   - **ЕСЛИ нет данных:** перейти к шагу 9а
9. **Вкладка "Информация о победителях":**
   - 9а) Если нет данных в "Договоры": найти таблицу "Информация о победителях"
   - 9б) Из таблицы в столбце **"Победитель"** извлечь:
     - БИН компании (12-значное число)
     - Наименование компании
10. Перейти во вкладку **"Протоколы"**:
    - Найти таблицу с протоколами итогов
    - Нажать кнопку **"Просмотреть протокол"** в столбце **"Протокол итогов"**
11. На открывшейся HTML-странице протокола:
    - Найти таблицу **"Расчет условных цен участников конкурса"**
    - По БИН победителя (из шага 9) найти соответствующую строку
    - Извлечь сумму из столбца **"Цена поставщика"**
12. **ВАЖНО: Если в шаге 8 были данные в "Договоры":**
    - Включить объявление в итоговый отчёт
    - Заполнить все столбцы кроме **"Цена победителя"** (оставить пусто)

#### Структура данных объявления

Для каждого объявления парсер собирает данные, выделенные на сайте сразу после поиска:

- **№** — порядковый номер
- **Наименование объявления** — название (содержит гиперссылку)
- **Способ** — способ закупки
- **Начало приема заявок** — дата/время начала
- **Окончание приема заявок** — дата/время окончания
- **Сумма, тг.** — сумма закупки
- **Статус** — текущий статус объявления

Плюс данные, спарсенные из вкладок объявления:

- **Наименование победителя конкурса** — из "Информация о победителях"
- **БИН победителя** — из "Информация о победителях"
- **Цена победителя** — из HTML-протокола (или пусто если "Договоры" не пусто)
- **Гиперссылка на объявление** — из колонки "Наименование объявления"

## Обработка ошибок

| Ситуация                                                           | Поведение                                                                                                                       |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Договоры по БИН не найдены                           | Записать строку с пометкой "Договоры не найдены", продолжить следующий БИН |
| Страница договора не загрузилась              | Пропустить договор, записать URL с пометкой "Ошибка загрузки"                            |
| Поле суммы пустое или не является числом | Считать значение = 0, пометить строку                                                                       |
| Timeout при загрузке страницы                           | Повторить попытку 2 раза, затем пропустить                                                            |
| Сайт временно недоступен                             | Остановить с сообщением об ошибке пользователю                                                  |

## Ограничения и важные замечания

1. **Скорость парсинга:** сайт госзакупок может работать медленно. Задержки между запросами снижены до 0.5–0.8 сек; ненужные ресурсы (изображения, шрифты, медиа) блокируются на уровне маршрутизации Playwright.
2. **Пагинация:** обязательно обработать случай когда договоров больше чем умещается на одной странице таблицы.
3. **Числа с форматированием:** суммы на сайте могут содержать пробелы и символы валюты — очищать перед конвертацией в float.
4. **Динамический контент:** сайт использует JavaScript-рендеринг, поэтому Playwright обязателен (requests/BeautifulSoup недостаточно).
5. **Anti-bot:** используется реалистичный User-Agent и заголовки Accept-Language; флаг `--disable-blink-features=AutomationControlled` скрывает признаки автоматизации.
6. **Фильтрация по дате:** не реализуется на данном этапе, оставить как TODO.
