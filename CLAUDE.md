# CLAUDE.md — Платформа анализа госзакупок

## Обзор проекта

Веб-платформа для автоматизированного сбора и анализа данных реестра договоров с сайта [goszakup.gov.kz](https://goszakup.gov.kz/). Пользователь вводит БИН компаний, система автоматически собирает данные по договорам, вычисляет разницу сумм и формирует Excel-отчёт.

**Стек:** Python + Streamlit + Playwright (или Selenium) + openpyxl
**Язык интерфейса:** Русский
**Авторизация на сайте:** не требуется

## Технический стек

| Компонент | Библиотека / Инструмент                                                                            |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| UI                 | `streamlit`                                                                                                          |
| Парсинг     | `playwright` (async, headless)                                                                                       |
| Excel              | `openpyxl`                                                                                                           |
| Прогресс   | `st.progress` + `st.status`                                                                                        |
| ИИ агент    | Claude API (`claude-sonnet-4-20250514`) — опционально для извлечения данных из HTML |

> **Примечание:** Playwright предпочтительнее Selenium — он стабильнее работает с динамическим JS-контентом сайта госзакупок.

## Функциональность

### 1. Форма ввода БИН

- Одно поле ввода БИН по умолчанию при старте
- Кнопка **"+"** для добавления дополнительных полей (динамически)
- Кнопка **"−"** для удаления поля
- Валидация: БИН должен состоять из 12 цифр
- Кнопка **"Запустить анализ"** — запускает весь пайплайн

```
[ БИН: ________________ ] [−]
[ + Добавить БИН ]
[ Запустить анализ ]
```

---

### 2. Алгоритм парсинга (scraper.py)

Для **каждого** введённого БИН выполняется следующая последовательность:

#### Шаг 1 — Навигация

1. Открыть `https://goszakup.gov.kz/`
2. Перейти: **Реестры → Договоры → Реестр договоров**

#### Шаг 2 — Фильтрация

3. В поле **"Поставщик"** ввести БИН компании
4. В поле **"Статус договора"** выбрать следующие статусы (мультивыбор):
   - `Действует`
   - `Передан. Действует`
   - `Создано доп.соглашение`
5. Нажать кнопку **"Найти"**

#### Шаг 3 — Сбор ссылок

6. Дождаться загрузки таблицы результатов
7. Собрать все гиперссылки на договоры из таблицы
8. Обработать пагинацию (если результатов несколько страниц — пройти все страницы)

#### Шаг 4 — Парсинг каждого договора

Для каждой ссылки:
9. Открыть страницу договора
10. В разделе **"Общее"** найти и извлечь:
    - `Краткое содержание договора на русском языке` → **текстовое поле**
    - `Общая сумма договора по итогам закупки` → **числовое поле**
    - `Общая итоговая сумма договора` → **числовое поле**
11. Вычислить разницу:
    ``   Разница = Общая сумма договора по итогам закупки − Общая итоговая сумма договора   ``
12. Сохранить: БИН, краткое содержание, разница, URL договора

---

### 3. Прогресс-бар

Отображать пользователю:

- Текущий обрабатываемый БИН (например: `Обработка БИН 123456789012... (1/3)`)
- Текущий договор (например: `Договор 45 из 120`)
- Общий прогресс-бар `st.progress()`
- Статусные сообщения через `st.status()` или `st.empty()`

---

### 4. Excel-отчёт (excel_export.py)

#### Структура файла

- Отдельный лист для **каждого БИН** (название листа = БИН компании)
- На каждом листе таблица со столбцами:

| № | Столбец                                 | Описание                                                                                               |
| -- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| A  | **БИН компании**              | БИН из поля ввода                                                                                |
| B  | **Краткое содержание**  | Текст из поля "Краткое содержание договора на русском языке" |
| C  | **Разница сумм (тенге)** | Сумма по итогам закупки − Итоговая сумма                                     |
| D  | **Ссылка на договор**     | Кликабельная гиперссылка на страницу договора                         |

#### Форматирование

- Заголовки: жирный шрифт, серая заливка
- Числа в столбце C: числовой формат с разделителем тысяч (`#,##0`)
- Столбец D: активные гиперссылки через `openpyxl` (синий цвет, подчёркивание)
- Ширина столбцов подстраивается под содержимое
- Шрифт: Arial 10

#### Итоговый лист "Сводка"

- Суммарная разница по каждому БИН
- Общий итог по всем БИН

---

### 5. Выгрузка файла

После завершения парсинга:

- Появляется кнопка **"⬇ Скачать Excel-отчёт"** (`st.download_button`)
- Файл именуется: `goszakup_report_YYYYMMDD_HHMMSS.xlsx`

## Обработка ошибок

| Ситуация                                                           | Поведение                                                                                                                       |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Договоры по БИН не найдены                           | Записать строку с пометкой "Договоры не найдены", продолжить следующий БИН |
| Страница договора не загрузилась              | Пропустить договор, записать URL с пометкой "Ошибка загрузки"                            |
| Поле суммы пустое или не является числом | Считать значение = 0, пометить строку                                                                       |
| Timeout при загрузке страницы                           | Повторить попытку 2 раза, затем пропустить                                                            |
| Сайт временно недоступен                             | Остановить с сообщением об ошибке пользователю                                                  |

## Ограничения и важные замечания

1. **Скорость парсинга:** сайт госзакупок может работать медленно. Рекомендуется добавить задержки между запросами (1–2 сек) чтобы не перегружать сервер.
2. **Пагинация:** обязательно обработать случай когда договоров больше чем умещается на одной странице таблицы.
3. **Числа с форматированием:** суммы на сайте могут содержать пробелы и символы валюты — очищать перед конвертацией в float.
4. **Динамический контент:** сайт использует JavaScript-рендеринг, поэтому Playwright обязателен (requests/BeautifulSoup недостаточно).
5. **Фильтрация по дате:** не реализуется на данном этапе, оставить как TODO.
