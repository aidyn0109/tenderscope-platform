# CLAUDE.md — Платформа анализа госзакупок

## Обзор проекта

Веб-платформа для автоматизированного сбора и анализа данных госзакупок с портала [goszakup.gov.kz](https://goszakup.gov.kz/). Поддерживает два режима: анализ реестра договоров по БИН поставщиков и анализ закупочных объявлений по дате протокола итогов.

**Стек:** Python + Streamlit + requests + BeautifulSoup + openpyxl
**Язык интерфейса:** Русский
**Деплой:** Render (PaaS), переменные окружения через Render Environment

---

## Технический стек

| Компонент                        | Библиотека / Инструмент                              |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| UI                                        | `streamlit`                                                            |
| HTTP-запросы                       | `requests`+`urllib3`(verify=False — казахстанский SSL) |
| Парсинг HTML протоколов  | `beautifulsoup4`                                                       |
| GraphQL API                               | `requests.post`к GraphQL эндпоинтам госзакупок    |
| Excel                                     | `openpyxl`                                                             |
| Прогресс                          | `st.progress`+ file-based polling (JSON файлы)                    |
| Авторизация платформы | HMAC-SHA256 токены, хэши паролей SHA-256                |

> **Playwright не используется.** Все данные получаются через официальный GraphQL API госзакупок с Bearer-токеном. HTML протоколы итогов скачиваются напрямую через requests.

| Параметр                        | Значение                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------ |

| Объявления endpoint           | https://ows.goszakup.gov.kz/v3/graphql                                         |

## Авторизация платформы (auth.py)

* Пользователи хранятся в `st.secrets["users"]` или переменных окружения Render
* Пароли хранятся как SHA-256 хэши
* Сессии — самодостаточные HMAC-SHA256 токены в URL-параметрах (TTL 7 дней)
* Секрет подписи: переменная окружения `AUTH_SECRET`

## Режим 1: Анализ реестра договоров (scraper.py)

### Форма ввода

* Одно поле БИН по умолчанию, кнопка **"+"** для добавления полей
* Валидация: ровно 12 цифр
* Кнопка **"Запустить анализ"**

### Алгоритм парсинга

GraphQL endpoint: `https://ows.goszakup.gov.kz/v2/graphql`

```graphql
query($filter: ContractFiltersInput, $after: Int) {
  contract(limit: 50, after: $after, filters: $filter) {
    id
    contract_number_sys
    description_ru
    contract_sum        # сумма БЕЗ НДС
    fakt_sum            # фактическая БЕЗ НДС
    supplier_biin
    sign_date
    ec_end_date
  }
}
```

**Фильтры:**

* `supplier_biin` — БИН поставщика
* `ref_contract_status_id` — `[190, 460, 450]` (Действует / Передан.Действует / Создано доп.соглашение)

**Маппинг полей:**

* `contract_number_sys` → номер договора
* `description_ru` → краткое содержание
* `sign_date` + `ec_end_date` → срок действия (ДД.ММ.ГГГГ — ДД.ММ.ГГГГ)
* `contract_sum` → итоговая сумма **без НДС**
* `fakt_sum` → фактическая сумма **без НДС**
* Разница = итоговая − фактическая
* URL: `https://goszakup.gov.kz/ru/egzcontract/cpublic/show/{id}`

### Excel-отчёт (excel_export.py)

**Лист "Договоры":**

| Столбец                                | Описание                                     |
| --------------------------------------------- | ---------------------------------------------------- |
| A — БИН компании                  | БИН поставщика                          |
| B — Номер договора              | Системный номер                        |
| C — Краткое содержание      | Описание на русском                 |
| D — Срок действия                | Дата начала — дата окончания |
| E — Итоговая сумма (тг)       | Без НДС                                        |
| F — Фактическая сумма (тг) | Без НДС                                        |
| G — Разница (тг)                    | E − F, отрицательные красным    |
| H — Ссылка на договор         | Гиперссылка                               |

**Лист "Сводка":** агрегированные итоги по каждому БИН + общий итог.

Файл: `goszakup_report_YYYYMMDD_HHMMSS.xlsx`

## Режим 2: Анализ объявлений (scraper_announcements.py)

### Форма ввода

```
[ Протокол итогов с: дата ] [ Протокол итогов по: дата ]
[ БИН компании-победителя: ____________ ] (необязательно, 12 цифр)
[ Запустить анализ ]
```

* **Даты** — диапазон дат публикации протокола итогов (`itogiDatePublic`)
* **БИН победителя** — необязательный фильтр. Если заполнен — возвращаются только объявления где этот БИН является победителем в любом лоте

### Алгоритм парсинга

GraphQL endpoint: `https://ows.goszakup.gov.kz/v3/graphql`

#### Шаг 1 — Список объявлений

```graphql
query($filter: TrdBuyFiltersInput, $after: Int) {
  TrdBuy(limit: 50, filter: $filter, after: $after) {
    id
    numberAnno
    nameRu
    totalSum
    countLots
    refBuyStatusId
    startDate
    endDate
    itogiDatePublic
    refTradeMethodsId
  }
}
```

**Фиксированные фильтры API:**

* `refBuyStatusId`: `[210, 220, 330, 350]`
* `refSubjectTypeId`: `2` (Работа)
* `totalSum`: `[1500000000, 999999999999]`

**Фильтрация по дате в Python:**

```python
filtered = [r for r in items
            if r.get("itogiDatePublic")
            and date_from <= str(r["itogiDatePublic"])[:10] <= date_to]
```

#### Шаг 2 — Договоры по объявлению

`Contract(filter: {trdBuyNumberAnno: numberAnno})` → если есть — `has_contracts=True`.

#### Шаг 3 — Протокол итогов

`TrdBuy(filter: {id: [ann_id]}) { Files { nameRu filePath } }` → ищем файл с `"Протокол итогов"` в названии → скачиваем HTML.

#### Шаг 4 — Парсинг HTML протокола

**Однолотовые** (`countLots == 1`):

* Победитель: таблица с `"победител"` / `"жеңімпаз"` в заголовке → `cells[1]`=имя, `cells[2]`=БИН
* Цена Тип 1 (обычный конкурс): таблица `"Цена поставщика"` → `bin_col+2`
* Цена Тип 2 (рейтингово-балльная): таблица `"суммарное количество баллов"` + `"выделенная сумма"` → `bin_col+1`

**Многолотовые** (`countLots > 1`) — функция `_parse_protocol_lots()`:

1. Находим русскую таблицу лотов (заголовок: `"лота"` + `"наименование"` + `"количество"`)
2. Собираем список лотов по порядку: `(lot_number, lot_name, lot_amount)`
3. Собираем все таблицы цен после таблицы лотов — по 1 на каждый лот
4. Победитель каждого лота = поставщик с **наименьшей ценой**

#### Шаг 5 — Subjects API (fallback для имени)

`Subjects(filter: {bin: winner_bin})` → `nameRu` если имя не найдено в протоколе.

#### Шаг 6 — Фильтр по БИН победителя

Если `filter_bin` задан — объявление включается в результат только если `filter_bin == record.winner_bin` или `filter_bin == lot.winner_bin` для любого лота.

### Структуры данных

```python
@dataclass
class LotRecord:
    lot_number: str      # "86606608-ОТ1"
    lot_name: str
    lot_amount: float    # выделенная сумма лота
    winner_name: str
    winner_bin: str
    winner_price: float

@dataclass
class AnnouncementRecord:
    number: int
    name: str
    method: str
    start_date: str
    end_date: str
    sum_amount: float
    status: str
    winner_name: str     # победитель первого лота
    winner_bin: str
    winner_price: float
    url: str
    has_contracts: bool
    error: str
    lots: list[LotRecord]  # все лоты (включая однолотовые)
```

### Excel-отчёт (excel_export_announcements.py)

**Один лист "Объявления"** — каждый лот на отдельной строке.

| Столбец                                     | Описание                                                                              |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| A — №                                            | Порядковый номер (только первая строка объявления) |
| B — Наименование объявления | Только первая строка                                                        |
| C — Способ                                  | Только первая строка                                                        |
| D — Начало приема заявок        | Только первая строка                                                        |
| E — Окончание приема заявок  | Только первая строка                                                        |
| F — Сумма закупки, тг.              | Только первая строка                                                        |
| G — Статус                                  | Только первая строка                                                        |
| H — № лота                                   | Для каждого лота                                                                |
| I — Наименование лота             | Для каждого лота                                                                |
| J — Наименование победителя | Для каждого лота                                                                |
| K — БИН победителя                   | Для каждого лота                                                                |
| L — Цена победителя, тг.          | Из протокола; пусто если `has_contracts=True`                           |
| M — Гиперссылка                        | Только первая строка                                                        |

* Дополнительные строки лотов выделены голубоватой заливкой (`EBF3FB`)
* Итоговая строка: суммы по столбцам F и L
* Файл: `goszakup_announcements_YYYYMMDD_HHMMSS.xlsx`

## Архитектура воркера (worker.py)

Subprocess, обменивается данными через JSON-файлы во временной директории.

**input.json (режим договоров):**

```json
{"bins": ["БИН1", "БИН2"], "progress_file": "path/progress.json"}
```

**input.json (режим объявлений):**

```json
{
  "mode": "announcements",
  "date": "YYYY-MM-DD",
  "date_to": "YYYY-MM-DD",
  "filter_bin": "123456789012",
  "progress_file": "path/progress.json"
}
```

* `filter_bin` — опционально, `null` если не задан
* output.json пишется атомарно (`.tmp` → rename) после каждой записи
* При досрочном завершении воркера app.py читает частичный output.json

## Обработка ошибок

| Ситуация                                     | Поведение                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------------- |
| Договоры по БИН не найдены     | Строка "Договоры не найдены"                       |
| Протокол не найден в Files          | `error = "Победитель не найден"`                      |
| Ошибка скачивания протокола | Запись ошибки, продолжение                         |
| Сеть недоступна                        | Retry 2 раза × 3 сек, затем ошибка                     |
| Числовое поле пустое               | `0.0`                                                                   |
| Воркер завершился досрочно   | Показ частичных данных + предупреждение |
| Таймаут воркера (>600 сек)          | Принудительная остановка                           |
