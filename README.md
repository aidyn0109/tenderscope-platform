# TenderScope

Веб-платформа для автоматизированного сбора и анализа данных государственных закупок Республики Казахстан с портала [goszakup.gov.kz](https://goszakup.gov.kz/).

Данные получаются через официальный GraphQL API госзакупок (`ows.goszakup.gov.kz`) по Bearer-токену; протоколы итогов и страницы лотов дополнительно разбираются из HTML. Результат каждого анализа выгружается в оформленный Excel-отчёт.

**Стек:** Python 3.11 · Streamlit · requests · BeautifulSoup · openpyxl
**Язык интерфейса:** русский
**Деплой:** Render (Docker)

---

## Возможности

Платформа закрыта авторизацией по логину/паролю и содержит два независимых режима анализа.

### Режим 1 — Анализ реестра договоров

Оценивает загрузку компаний-поставщиков: сколько работ у них в договорах за 2026 год относительно заданного максимального дохода.

На входе — список пар «БИН (12 цифр) + максимальный доход в тенге». Поля добавляются кнопкой **＋ Добавить БИН**.

Для каждого БИН собираются договоры со статусами «Действует», «Передан. Действует», «Создано доп. соглашение», отфильтрованные по предмету «Работа» и году создания `2026`. По каждому договору из раздела «Предметы договора» рассчитываются:

| Показатель | Как считается |
| --- | --- |
| Сумма 1 (плановая/утверждённая) | `planSum` за максимальный `finYear` основного предмета договора |
| Сумма 2 (фактически исполненная) | сумма `factSum` за все годы **кроме** максимального |
| Общая итоговая сумма | Сумма 1 − Сумма 2 |
| Результат показателя загрузки | Общая итоговая сумма ÷ Максимальный доход |

Индикатор в сводке: 🟢 при загрузке ≤ 1.5, 🔴 при загрузке > 1.5.

### Режим 2 — Анализ объявлений

Ищет объявления, у которых **есть победитель, но ещё нет договора** — то есть закупки, где договор ожидается.

На входе — только диапазон дат публикации протокола итогов (`itogiDatePublic`). Фильтры API фиксированы: статус «Договор подписан», предмет «Работа», способы закупки «Рейтингово-балльная система» и «Строительство под ключ».

Алгоритм по каждому объявлению:

1. Найти в `Files` файл, содержащий «Протокол итогов» → скачать HTML. Нет протокола → пропуск.
2. Разобрать победителя (имя + 12-значный БИН) из таблицы протокола. Нет победителя → пропуск.
3. Проверить `Contract(trdBuyNumberAnno: …)`. Договор уже есть → пропуск.
4. Собрать «Сумму 1 год»: сумма `sum1` планов лотов за `plnPointYear = 2026`.

## Архитектура

```
TenderScope/
├── app.py                          # Streamlit UI: авторизация, навигация, формы, прогресс, выгрузка
├── worker.py                       # Парсинг в отдельном процессе, обмен через JSON-файлы
├── auth.py                         # Логин, SHA-256 хэши паролей, HMAC-подписанные сессии
│
├── scraper.py                      # Режим 1: договоры (GraphQL v2 + v3 ContractSpecSum)
├── excel_export.py                 # Режим 1: листы «Сводка» и «Договоры»
│
├── scraper_announcements.py        # Режим 2: объявления (GraphQL v3 + HTML протоколов)
├── excel_export_announcements.py   # Режим 2: лист «Объявления»
│
├── requirements.txt
├── render.yaml
└── CLAUDE.md                       # Рабочие заметки по проекту
```

### Модель исполнения

Парсинг вынесен в подпроцесс (`worker.py`), запускаемый из `app.py` через `subprocess.Popen`. Обмен идёт через JSON-файлы во временной директории:

| Файл | Назначение |
| --- | --- |
| `input.json` | параметры запуска (режим, БИНы или даты, путь к `progress.json`) |
| `progress.json` | текущий прогресс, читается UI по опросу |
| `output.json` | накапливаемые записи; переписывается **после каждой** обработанной записи |
| `worker.log` | stdout воркера, показывается в UI при ошибке |

`output.json` пишется атомарно (`.tmp` → `os.replace`), поэтому UI никогда не прочитает обрезанный файл. Флаг `done=True` в `progress.json` выставляется только после полного завершения. Если воркер убьют (например, OOM на Render), `app.py` подхватит частичные данные из `output.json` и покажет их с предупреждением. Есть кнопка **⛔ Остановить сбор данных** и принудительный таймаут 600 секунд.

### Конфигурация API

| Параметр | Значение |
| --- | --- |
| Договоры | `https://ows.goszakup.gov.kz/v2/graphql` |
| Предметы договоров, объявления, лоты | `https://ows.goszakup.gov.kz/v3/graphql` |
| Авторизация | `Authorization: Bearer <GOSZAKUP_TOKEN>` |
| SSL | `verify=False` + `urllib3.disable_warnings()` — казахстанский корневой сертификат |
| Лимит на запрос | 50 записей, пагинация через `extensions.pageInfo.hasNextPage` / `lastId` |
| Потолок выборки | 10 000 записей |
| Retry | 2 повтора с паузой 3 с |
| Таймауты | 60 с на GraphQL, 30 с на HTML-страницы |

> Playwright и браузерная автоматизация не используются — всё через `requests`.

## Локальный запуск

```bash
git clone https://github.com/aidyn0109/tenderscope-platform.git
cd tenderscope-platform

python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Linux / macOS

pip install -r requirements.txt
```

Создайте `.streamlit/secrets.toml` (файл в `.gitignore` и в репозиторий не попадает):

```toml
goszakup_token = "<Bearer-токен API госзакупок>"
auth_secret    = "<случайная строка для подписи сессий>"

[users.admin]
password_hash = "<SHA-256 хэш пароля>"
role          = "admin"
display_name  = "Администратор"
```

Хэш пароля:

```bash
python -c "import hashlib,sys; print(hashlib.sha256(sys.argv[1].encode()).hexdigest())" "мой-пароль"
```

Запуск:

```bash
streamlit run app.py
```

Скраперы можно проверять и отдельно, без UI:

```bash
python scraper.py 031240001439
python scraper_announcements.py 2026-07-04 2026-07-28
```

## Деплой на Render

Сервис описан в [render.yaml](render.yaml): нативный Python-runtime, сборка `pip install -r requirements.txt`, запуск `streamlit run app.py --server.port $PORT --server.address 0.0.0.0`.

> Если сервис на Render был создан вручную через дашборд, а не через Blueprint, `render.yaml` игнорируется — Build/Start Command в этом случае задаются в настройках сервиса и должны совпадать с указанными выше.

Переменные окружения задаются в разделе Render → Environment; они же служат заменой `secrets.toml`:

| Переменная | Назначение |
| --- | --- |
| `GOSZAKUP_TOKEN` | Bearer-токен GraphQL API госзакупок |
| `AUTH_SECRET` | секрет подписи HMAC-токенов сессий (**обязателен** на проде) |
| `ADMIN_HASH` | SHA-256 хэш пароля администратора |
| `USER_HASH` | SHA-256 хэш пароля пользователя |
| `ADMIN_ROLE` / `USER_ROLE` | роли, по умолчанию `admin` / `user` |
| `ADMIN_DISPLAY` / `USER_DISPLAY` | отображаемые имена |

Порядок разрешения секретов в коде: `st.secrets` → переменные окружения. Если `AUTH_SECRET` не задан, используется встроенное значение по умолчанию — на продакшене это позволило бы подделать подпись сессии, поэтому переменную нужно выставить обязательно.

## Авторизация платформы

Сессии — самодостаточные токены `<base64url(payload)>.<HMAC-SHA256[:32]>`, которые хранятся в URL-параметре `auth` и не требуют серверного состояния. TTL — 7 дней. Пароли сравниваются по SHA-256 хэшу, подпись проверяется через `hmac.compare_digest`.

## Обработка ошибок

| Ситуация | Поведение |
| --- | --- |
| Договоры по БИН не найдены | строка-заглушка «Договоры не найдены (после фильтрации)» |
| Протокол итогов не найден или не скачался | объявление пропускается |
| Победитель не распознан в протоколе | объявление пропускается |
| Сеть недоступна | 2 повтора × 3 с, затем ошибка в лог и в `errors` |
| Пустое числовое поле | `0.0` |
| Воркер завершился досрочно | частичные данные из `output.json` + предупреждение |
| Таймаут воркера (> 600 с) | принудительная остановка процесса |

## Справочники кодов

**Статусы объявлений (`refBuyStatusId`)** — 210 Завершено · 220 Формирование протокола итогов · 330 Итоги опубликованы · **350 Договор подписан** (используется: только у него заполнен `itogiDatePublic`)

**Статусы договоров (`ref_contract_status_id`)** — **190 Действует** · **450 Создано доп. соглашение** · **460 Передан. Действует** (жирным — используемые)

**Способы закупки (`refTradeMethodsId`)** — 1 Конкурс · 2 Аукцион · 3 Запрос ценовых предложений · 4 Из одного источника · 5 Запрос предложений · 6 Закупка из одного источника · **32 Рейтингово-балльная система** · **188 Строительство «под ключ»** · 201 Конкурс с предквалификацией

**Тип предмета (`refSubjectTypeId` / `ref_subject_type_id`)** — `2` Работа (используется в обоих режимах)
